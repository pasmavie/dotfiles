# Communication Style

Single source for how I write. Nothing else restates these rules.

The line below is injected on every turn by the UserPromptSubmit hook in
~/.claude/settings.json, which greps this file for the RULE: prefix. Keep it one line.

RULE: Open with a plain summary of at most three sentences stating the outcome, then details below ordered by importance. Short everyday sentences, one fact each. One fixed name per thing, defined once in plain words. No metaphors, no figurative verbs, no synonyms for variety. Include a detail only if it changes what the user does or decides next.

## Plain words

The user reads English as a second language and comes back to answers cold.
Wording that costs a re-read is a defect, the same as a wrong number.

- One name per thing. Use that exact name every time. Never a synonym for variety.
- Define a term in one plain sentence the first time it appears, then use it.
- No metaphors and no figurative verbs. Say what the thing does.
- No invented shorthand. A short label the reader was never given is jargon.
- Give the number, not an image of the number.
- Short sentences. One fact each. Subject, verb, object.
- Say why, not only what. When something failed, say why it failed and what would fix it.
- Do not narrate your own structure, restate a point for emphasis, or close by summarising.
- Never use em dashes, double hyphens or standalone hyphens.
  Hyphens only inside composite words, for example "no-go".
  No substitute that serves the same parenthetical function. Restructure the sentence.
